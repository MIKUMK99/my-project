# 邻里券

**每周五打开发券页，看清该请回谁，再确认发送。**

给社区超市「邻里购」的会员运营用。店里 1,000 名会员，每周五下午由她一个人决定：这一批「满 99 减 20」短信发给谁。

郑深源 · 2026 年 10 月

**虚构说明。** 超市、会员、手机号和购买记录都是为这个作品编造的样例，不对应任何真实的人或企业。这是一次产品设计练习：产品说明、数据清洗、可点击原型、PRD 和作品集放在同一个仓库里。

## 先看原型

用浏览器打开 [`原型/index.html`](原型/index.html)。不需要安装依赖，也不需要启动服务器。页面上的数字全部由 [`原型/data.js`](原型/data.js) 算出来。

GitHub 网页里的 HTML 预览不会执行脚本。要看到 1,000 / 420 / 334，请把仓库克隆到本地再打开，或开启 GitHub Pages（根目录的 `index.html` 会进入原型）。

统计日是 **2026-10-20**。首页三个数：

| 会员总数 | 沉睡客 | 今天将要发送 |
| --- | --- | --- |
| 1,000 | 420 | 334 |

发送条件：沉睡客，有手机号，近 7 日没来过。

![发券首页：会员总数 1000、沉睡客 420、今天将要发送 334](photos/点开主界面.png)

## 用完之后她能决定什么

她能决定这一期券发给谁。名单里的每一个人，她都能说出为什么发；不在名单里的人，她也能说出为什么不发。

她原来的系统只有一个「全体群发」按钮：常来的老客也在里面，看不出这周谁刚来过，发完也说不清发给了谁。

一次周五操作的步骤写在 [`md文件/02_使用流程.md`](md文件/02_使用流程.md)。

## 这期只做这一件事

只解决「把好久没来的人请回来」。下面这些故意不做，原因和代价在 [`md文件/03_取舍.md`](md文件/03_取舍.md)。

- 不做新客券、生日券、满额加价券
- 不用模型选人，用写死的规则，方便她向店长解释
- 近 7 日已经来过的人不发
- 没有手机号的人留在沉睡客统计里，不进入发送名单
- 不做 BI 和趋势图

`原型/funnel.html` 只用来核对三个数，不在产品导航里。

两个容易看成算错的数：首页沉睡客 **420** = 会员列表里的沉睡客 **380** + 数据对不上 **40**。首页「近 7 日买过」**398** = 常购客里这周也来过的 **238** + 互斥分类里的本周到店 **120** + 数据对不上 **40**。从 420 到 334 的加减是 `420 − 56 − 40 + 10 = 334`。

## 在本地复核三个数

需要 Python 3，不需要安装第三方包。在仓库根目录执行：

```text
python scripts/run_sql.py
python scripts/run_list.py
```

`run_sql.py` 应打印会员总数 1000、沉睡客 420、今天将发送 334。默认读取 `数据清洗表格/清洗过后.csv`。

清洗表如果改过，用下面的命令重写原型数据，不要手改 `原型/data.js`：

```text
python scripts/csv_to_data_js.py --date=2026-10-20
```

作品集的分页稿是 `作品集_邻里券-分页v1.0.pdf`，共 32 页，A4 横向。正文仍以 `md文件/作品集_邻里券.md` 为准。`make_v12.py` 是早先按大节硬分页的脚本，不要用它覆盖分页 v1.0。
